# Team Weaver

Build a web app called ProjectMatch — a team formation platform that helps people form project teams (for hackathons, competitions, research, or startups) by matching project leaders with candidates based on skills, availability, experience, and requirements. The core interaction is a swipe-based recommendation system: project leaders swipe through ranked candidate cards to invite members; candidates swipe through ranked project cards to request to join. No traditional backend/auth needed — use a lightweight session (name-based) and store data in-memory or in a simple database (Supabase if available). COLOR, TYPE, AND VISUAL DIRECTION - Avoid generic "AI app" defaults (no cream background + terracotta accent, no plain dark + neon-green). - Palette: deep indigo-navy background (#1B1B2F) for app chrome, soft lavender-white cards (#F5F3FF), teal-green accent for "match/invite" (#06D6A0), rose accent for "skip/decline" (#EF476F), amber for match-score badges (#FFD166). - Typography: a bold geometric display font (e.g. Space Grotesk) for headings, a clean readable body font (e.g. Inter), and a monospace font (e.g. JetBrains Mono) specifically for skill tags/chips — skill tags should visually read like code tags to reinforce the "skills" theme. - Cards should feel like stacked ID badges / game cards, not generic list rows. - Rounded corners (12–16px) on cards, flat design, no heavy shadows or gradients. LANDING PAGE - App name "ProjectMatch" with tagline: "Find your team. Build what's next." - Two large entry buttons: "I'm leading a project" and "I want to join a team". - Below the buttons, a brief 3-step visual explainer of how matching works (post/profile → get ranked matches → swipe to connect). FLOW A: TEAM LEADER SIGN-UP / "LOGIN" A single onboarding form (no real auth — just a name-based session) capturing: - Leader name (text input) - Experience level (dropdown: Beginner / Intermediate / Advanced / Expert) - Project title (text input) - Project description (textarea) - Duration (dropdown or text: e.g. "1 week", "1 month", "3 months", "Ongoing") - Skills required for the project (multi-select tag input — user can type and add multiple skill tags, e.g. "React", "UI Design", "Data Engineering") - Team size needed (number input) - Location (text input, with a toggle for "Remote OK") - Additional information (optional textarea — e.g. project links, meeting expectations, compensation/equity if any) On submit → creates a Project record and routes to the Leader Dashboard. FLOW B: "JOIN A TEAM" SIGN-UP / "LOGIN" A single onboarding form capturing: - Name (text input) - Skills (multi-select tag input, same tag component as leader form so skills match consistently) - Experience level (dropdown: Beginner / Intermediate / Advanced / Expert) - Availability (dropdown: e.g. "< 5 hrs/week", "5–10 hrs/week", "10–20 hrs/week", "20+ hrs/week") - Type of project ready to join (multi-select: Hackathon / Startup / Research / Competition / Open Source / Freelance-style) - Interests (optional tag input — domains they care about, e.g. "Fintech", "Health", "Climate") On submit → creates a Candidate profile and routes to the Candidate Dashboard. LEADER DASHBOARD - Header shows project title, description, duration, location, and a progress indicator ("3 of 5 roles filled"). - A "Find Members" button opens the Swipe Deck. - A "Your Team" section listing accepted members with their skills. - A "Pending Invites" section listing people invited but not yet responded. LEADER SWIPE DECK (core interaction) - Stack of candidate cards, one at a time, showing: name, avatar/initials, experience level, availability, top 3 matching skills (highlighted), and a match score % badge (amber, top-right of card). - Swipe right (or tap a check button) = send invite. Swipe left (or tap an X button) = skip, move to next card. - Cards can be swiped via drag gesture AND fallback buttons (for accessibility/no-touch). - Important scoring logic — implement this exactly: - The candidate pool is ranked using a weighted score: (matching skills × 3) + (availability fit × 2) + (interest overlap × 1). - Gap-aware re-ranking: as members are accepted onto the team, recompute "still-needed skills" = original required skills minus skills already covered by accepted members. Re-rank the remaining swipe deck against this updated gap, not the original static list, so the leader is always shown people who fill what's actually missing. - Empty state when deck is exhausted: "No more matches right now — check back as more candidates join." CANDIDATE DASHBOARD - "Invites" tab: cards for incoming invites from leaders (project title, required skills, leader's experience level, duration) with Accept / Decline actions. - "Discover Projects" tab: a second swipe deck, this time projects ranked for the candidate using the same scoring logic in reverse (candidate's skills vs project's needed skills). Swiping right sends a "request to join" that appears in the leader's Pending Invites for one-click accept. - "My Teams" tab: list of projects the candidate has joined. GLOBAL NAVIGATION - Persistent top bar with app name, and a simple role-switcher/profile menu (for demo purposes, allow switching between the leader view and any candidate profile without full authentication). DATA MODEL (for reference — implement as the underlying schema) User: { id, name, skills[], interests[], availability, experienceLevel, projectTypesInterested[] } Project: { id, title, description, leaderName, leaderExperience, requiredSkills[], teamSize, duration, location, remoteOk, additionalInfo } Invite: { id, projectId, userId, direction: "leader_to_candidate" | "candidate_to_leader", status: "pending" | "accepted" | "declined" } SEED DATA Pre-populate with 6–8 demo candidate profiles (varied skills: React, UX Design, Data Engineering, ML, Backend, Product) and 2–3 demo projects, so the swipe decks are populated immediately without requiring manual data entry to demo. EXPLICIT USER FLOW TO IMPLEMENT END-TO-END 1. Landing page → choose "Leading a project" or "Join a team" 2. Fill respective onboarding form → submit 3. Leader: dashboard → Find Members → swipe deck → invite sent 4. Candidate (switch role/profile): sees invite in Invites tab → Accept 5. Back to Leader dashboard: accepted member now appears in "Your Team", and remaining swipe deck re-ranks based on updated skill gap 6. Candidate can also independently browse Discover Projects → swipe right → leader sees it as a pending invite to accept
